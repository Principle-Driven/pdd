# SITE-01 — Lead with the benefit
Token: SITE-01
Version: v1

## Statement

Explain the useful outcome before the mechanism. A reader must know what time, complexity, or risk the principle removes.

The summary and detail page must both state this benefit.

## Rationale

A technical rule can be correct but still feel abstract. Readers will not accept its tradeoff when they cannot see its value.

Agents can copy the rule’s language without using its judgment. A clear benefit helps them choose the correct action.

## Implications

- Each catalog entry has a `benefit` field.
- Each summary describes an outcome, not only a mechanism.
- Each detail page shows the benefit near the top.
- Each example connects the rule to saved work or removed risk.

## Sanctioned exceptions

None.
